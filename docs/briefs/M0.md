# M0 브리프 — 스캐폴드

구현자: Opus 5 (medium) · 발주: 오케스트레이터 · 2026-07-28

## 0. 먼저 읽을 것 (순서대로)

1. `PLAN.md` — §5(스택 결정), §6(아키텍처), §8 M0 행, §9(핸드오프 규약)
2. `docs/research/architecture-hosting.md` — §1(저장소 추상화 + StorageAdapter 인터페이스 스케치), §4(프론트엔드 스택)

## 1. 목표

프로젝트 루트(이 저장소)에 앱 스캐폴드를 세운다. UI 완성도는 요구하지 않는다(그건 M2+). M0은 배관이다.

## 2. 산출물

1. **Vite + Svelte 5 + TypeScript(strict)** 프로젝트. SvelteKit이 아닌 순수 Vite + Svelte (정적 SPA, hash routing이므로 Kit 불필요 — 단, 검토 후 Kit adapter-static이 명백히 유리하면 M0-RESULT에 근거를 쓰고 채택 가능).
2. **Hash routing** — 의존성 최소(직접 구현 또는 초경량 라이브러리). 라우트: `#/` (프로필 선택), `#/home` (프로필 홈 placeholder), `#/settings`.
3. **`vite-plugin-pwa`** — 오프라인 캐시, 매니페스트.
4. **저장소 계층** `src/lib/storage/`:
   - `types.ts` — `StorageAdapter` 인터페이스 (profiles, progress, srsCards, settings CRUD — 리서치 문서 §1.1 스케치 기반, Promise 기반)
   - `dexie-adapter.ts` — Dexie.js 구현
   - `rest-adapter.ts` — 인터페이스만 구현한 stub (본 구현은 M6, `/api/health` probe 로직은 지금 작성)
   - `index.ts` — `createAdapter()` 런타임 감지 (800ms 타임아웃 probe)
5. **멀티 프로필 CRUD** — 생성/선택/이름변경/삭제, IndexedDB 저장, 마지막 활성 프로필 ID만 localStorage.
6. **i18n** — Paraglide JS(inlang) vs svelte-i18n 비교 후 하나 확정(근거를 M0-RESULT에 기록). 기본 `ko` + `en` 메시지 파일, 프로필별 언어 설정 + 스위처(설정 화면). 레슨 콘텐츠 로케일 키 규약(`{ko, en}` + ko 폴백)은 타입만 정의.
7. **GitHub Actions** `.github/workflows/`:
   - `ci.yml` — push/PR 시 `npm run check` + `npm test` + `npm run build`
   - `deploy.yml` — main push 시 `actions/deploy-pages`로 배포. **Vite `base: '/mathemagics-interactive/'`** 필수.
8. **Vitest** 셋업 + 최소 테스트: StorageAdapter 계약 테스트(DexieAdapter를 fake-indexeddb로), createAdapter 폴백 테스트.

## 3. 완료 기준

- `npm run check`(svelte-check) · `npm test` · `npm run build` 전부 통과 — 출력 원문을 M0-RESULT에 포함.
- 빌드 산출물이 hash routing으로 base path 하에서 동작(로컬 preview로 확인).
- 프로필 생성 → 새로고침 → 유지, ko↔en 스위칭 동작 (preview에서 수동 확인 후 결과 기록).

## 4. 규약 (PLAN.md §9 요약 + 추가)

- TS strict. 의존성 최소주의 — 추가하는 모든 패키지에 한 줄 사유.
- 커밋은 로컬에서 conventional commits로 쪼개서 할 것. **push 금지** (오케스트레이터가 검수 후 push).
- `mathemagics.pdf`는 절대 건드리지/커밋하지 말 것 (.gitignore에 있음).
- 결과 요약은 `docs/briefs/M0-RESULT.md`에 작성: 결정 사항(근거 포함), 파일 트리, 검증 출력, 미해결 이슈. 대화에는 경로만 보고.
- 라이브러리 최신 사용법이 불확실하면 context7로 문서 확인 (Svelte 5 runes, vite-plugin-pwa, Dexie 4).
