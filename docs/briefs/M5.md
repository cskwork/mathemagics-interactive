## 1. 목표

세로셈 렌더러가 진가를 발휘하는 지필 트랙(6장)과, 이 앱의 동기 설계 정점인 공연 모드·마술 콘텐츠(9장)를 완성한다.

## 2. 산출물

1. **지필 엔진 확장** — 6장은 유일한 우→좌·쓰기 계열임에 주의:
   - 열 덧셈(여러 수 세로 합, 올림 위첨자)
   - 크리스크로스 곱셈(2×2~5×5, **1-2-3-2-1 대각선 리듬** — 스텝마다 해당 대각선 쌍 하이라이트)
   - 지필 제곱근(두 자리 그룹 나누기, 자리별 추정)
   - 모드섬 검산(9 버리기·11 버리기 — 4장 배수판정과 연결)
2. **렌더러 확장** — SVG 대각선 오버레이(크리스크로스), 모드섬 동그라미 표기, 여러 피연산자 행, 제곱근 그룹 구분선.
3. **"오답 잡아내기" 게임** — 완성된 계산 중 틀린 것을 모드섬으로 찾아내는 문제 유형(검산이 마술처럼 느껴지는 연출).
4. **공연 모드** `#/stage` — **opt-in**: 정확도 게이트(M3) 통과 스킬만 입장. 무대 프레임(막·조명 수준의 경량 연출), 비교 대상은 오직 자기 기록(개인 최고 갱신 축하), 리더보드·타인 비교 없음. 기록은 프로필별 저장.
5. **수학 마술 콘텐츠(9장)** — 스킬트리 해금 슬롯(M4)에 실제 콘텐츠: 트릭 시연 → 비밀 공개(원리 = 배운 기법) → 연습 → "가족에게 보여주기" 미션 카드. 9종 중 앞 장 원리와 직결되는 것부터 우선.
6. **레슨·SRS 연동** — 지필 기법도 레슨 5단계·SRS 카드 체계에 편입.

## 3. 완료 기준

- 지필 엔진 단위 테스트(독립 계산 대조 + 모드섬 속성 테스트: mod-sum 불일치 ⇔ 오답).
- preview 수동 확인: 크리스크로스 3×3 스텝 리듬 재생, 오답 잡아내기 1판, 공연 모드 기록 갱신 흐름 — 기록.
- `npm run check` · `npm test` · `npm run build` 통과 — 출력 원문 첨부.
