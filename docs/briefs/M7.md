## 1. 목표

현재 UI는 "읽을 수 있는 최소치"(M0 `app.css` 주석 그대로)이다 — 시스템 폰트, 어디나 같은 카드 리듬, 버튼 전부 동일 표면, 헤더는 제목+태그라인 일색. 이것이 **AI 슬롭**(어떤 LLM이 찍어낸 것 같은 무미한 기본값)의 전형이다.
M7은 이 앱에 **의도적이고 고유한 시각 언어**를 입힌다 — 벤저민식 암산의 본질("무대에서 마술을 부리는 마술사")을 UI로 번역한다. 폴리시·접근성·연령 톤(유치함 배제)이 완료 기준에 들어간다.

## 2. 디자인 방향 — "The Stage" (무대)

**유일한 디자인 훅**: 이 앱은 교재가 아니라 **마술사의 무대**다. 학습자는 관객 앞에 선 마술사다(PLAN §4.2-8 "마술 공연" 프레임과 정합). 이 은유는:
- 기존 다크+앰버 팔레트(`--bg:#0f1020`, `--accent:#ffc94d`)를 **버리지 않고 정당화**한다 — 앰버는 객석 조명·스포트라이트, 다크 서피스는 객석·무대 바닥. (리디자인 규약: 기존 팔레트 보존 우선)
- 다른 수학 앱(Duolingo Math 의 캐릭터·Khan 의 카드)과 시각적으로 겹치지 않는다.
- 8–13세 톤에 맞는다 — 마스코트가 아니라 "공연자" 정체성(PLAN §7.2).

**구체적 모티프 (토큰·컴포넌트에 구현)**:
- **스포트라이트**: 주요 행동 영역(현재 문제·CTA)에 앰버 방사형 그라디언트 `radial-gradient` 를 살짝 깔아 "조명이 쏟아진 무대 중앙" 연출. 과하지 않게 — 배경 대비 6–10% 밝기 차이.
- **커튼/프로시니엄**: 화면 상단 가장자리에 아주 얇은 앰버 선(1px) 또는 미니멀한 좌·우 수직 그라디언트로 무대 프레임 암시. 과하면 유치해진다 — 최소치.
- **막 올림/막 내림**: 레슨·세션 시작/종료 전환에 가벼운 수직 reveal(커튼이 올라간다) — `prefers-reduced-motion` 시 즉시 전환. StepPlayer 의 fade 대체 가능.
- **번호판/숫자**: 세로셈 숫자는 "무대 위 카드" — ColumnGrid 셀에 미세한 depth(내장 그림자 1단)로 카드처럼. 이미 `tabular-nums` 는 잘 되어 있다.

## 3. 산출물

1. **디자인 토큰 시스템** `src/lib/ui/tokens.css` (신규, `app.css` 의 `:root` 를 이주·확장) — 모든 색·폰트·간격·반경·그림자·동작 시간이 **이름붙은 토큰**으로. inline OKLCH/hex/`rgb()` 금지(hallmark 규약 #3). 의미론적 레이어: `--stage-floor`(가장 어두움) · `--stage-mid` · `--stage-lit`(스포트라이트 받은 영역) · `--spotlight`(앰버) · `--spotlight-ink` · `--applause`(성공, 초록) · `--miss`(오답, 적색) · `--house-light`(muted 텍스트). 다크/라이트 두 `color-scheme` 모두(`prefers-color-scheme` 고려 — 단 v1 은 다크 기준, 라이트는 토큰만预留).
2. **타이포그래피 시스템** — 시스템 폰트 일변도를 교체. **2+1 폰트 규약**(hallmark): 디스플레이 1종 + 본문 1종 + (옵션)숫자 전용 1종. 한글+영문 동시 지원(ko 기본)해야 하므로 Google Fonts 무료 폰트 또는 시스템 한글 폰트 조합. **이탤릭 헤더 금지**(hallmark 규약 #6). 제안 방향(착수 시점 재확인·사유 기록): 디스플레이 = "Pretendard" 또는 "Noto Sans KR" 무게 800 본문 = 동일 400/500, 숫자 = "SUIT" 또는 `tabular-nums` 기반. 번들 가중치 vs 시각 이익 균형 — `font-display: swap` 필수.
3. **레이아웃 리듬 재구성** — 현재 "h2 + 카드 스택" 일변도를 깬다. 화면별 고유 리듬:
   - **App.svelte 헤더**: 제목+태그라인 평등 배치 → **프로시니엄 프레임**(좌측 작은 로고/월드마크 + 우측 LocaleSwitcher, 하단 얇은 앰버 선). 활성 프로필 있으면 프로필 칩(아바타+이름)이 헤더에 상주.
   - **ProfilePicker**: 카드 목록 → **"오늘의 공연자 선택"** — 프로필이 무대 프로그램 팜플렛의 출연진 명단처럼 정렬. 빈 상태는 "첫 공연자를 등록하세요" 카피(i18n).
   - **Home**: placeholder → **백스테이지 대시보드 뼈대** — "오늘의 공연"(연습/레슨 입장 CTA, 큼직한 스포트라이트 카드), "내 무대 репер토ire"(앞으로 학습할 기법 미리보기, M2+ 데이터 없으면 자리표). M2 이후 콘텐츠가 채울 자리를 구조만.
   - **Playground**: 개발용이지만 폴리시 적용 — 컨트롤은 "조명실" 패널 느낌(사이드 또는 하단 접이식), 무대 중앙은 계산 그리드.
4. **인앱 다이얼로그 컴포넌트** `src/lib/components/Dialog.svelte` (신규) — M0 인계 이슈 #3 해결. 네이티브 `prompt`/`confirm` 을 모달로 교체. 부모 게이트(architecture-hosting §5 — 파괴적 행동 전 "이것은 어른이 확인해야 해" 간단 과제, 예: "삭제하려면 '삭제' 라고 쳐주세요" 또는 간단 산수). ProfilePicker 이름변경/삭제에 적용. **포커스트랩·ESC 닫기·배경 클릭 닫기·`aria-modal`·`role="dialog"`** 필수.
5. **버튼 시스템 고도화** — 현재 단일 표면을 **역할별 음성**로: `primary`(스포트라이트/앰버, 주 행동) · `secondary`(무대 표면) · `ghost`(텍스트 전용, 보조) · `danger`(miss/적색). 각 버튼은 **8 상태 전부**(default/hover/focus-visible/active/disabled/loading/error/success — hallmark 컴포넌트 규약) 코드로 제공. NumPad 버튼은 "숫자 카드" 음성.
6. **마이크로인터랙션 정제** (3개 이하, hallmark 규약): `spotlight-sweep`(스포트라이트 스캔 — 정답 시) · `curtain-rise`(세션/레슨 진입 시 가벼운 수직 reveal) · `card-settle`(셀 채움 시 미세 바운스). 모두 `prefers-reduced-motion` 즉시 전환.
7. **접근성 실측 준비** — M0/M1 인계 이슈. `aria-live` 낭독 영역 시각적으로도 보이게(작은 자막바), 포커스 링 고대비화(앰버 3px → 좀 더 두꺼운 링 + 오프셋), 키보드 탭 순서 = 시각 순서 점검. VoiceOver/NVDA 실측은 여전히 환경 한계상 명시적 미검증으로 남김(솔직 기록).

## 4. 변경하지 않는 것 (리디자인 경계 — 준수 필수)

- **라우트**: `#/profiles`, `#/home`, `#/settings`, `#/dev/playground` — 추가·삭제·이동 없음.
- **엔진·스토리지·라우터·i18n 메시지 구조**: `src/lib/{engine,storage,router,i18n,content,profiles}/**` 는 건드리지 않는다. 단 UI 문자열이 새로 필요하면 `messages/{ko,en}.json` 에 **추가** 만(기존 키 삭제/변경 금지 — M0-M1 컴포넌트가 참조).
- **컴포넌트 소유권**: ColumnGrid/StepPlayer/DigitInput/NumPad 의 *props 계약*은 유지. 내부 마크업·`<style>` 은 자유롭게. Playground 의 쿼리 파라미터 계약 유지.
- **PLAN §7.2 경도(硬) 제약**: 터치 타깃 ≥48px · 본문 ≥16px · `prefers-reduced-motion` 준수 · 다크패턴 제로 · 손실-회피 압박 금지 · 리더보드/타인 비교 금지 · 8–13세 톤(유치함 배제).
- **의존성 최소주의**: 새 런타임 의존성은 폰트( `<link>` 또는 `@fontsource` 한정) 외에 원칙 금지. CSS 아트/SVG 우선(hallmark 규약). framer-motion/gsap 금지.

## 5. 완료 기준

- **안티-슬롭 자기비판 스탬프**: 각 변경 컴포넌트 상단에 `/* Hallmark · P_ H_ E_ S_ R_ V_ */` 6축(Philosophy·Hierarchy·Execution·Specificity·Restraint·Variety) 1–5 점. 3 점 미만 축은 개정. RESULT 에 점수와 근거 기록.
- **토큰 잠금 검증**: `rg '(#[0-9a-fA-F]{3,8}|oklch\(|rgb\()' src/components src/routes src/lib/ui` 가 inline 색값 0건 반환(토큰 참조만 허용). 폰트 `font-family:` 도 토큰 참조만.
- **반응형 검증**: 320 / 375 / 414 / 768 px 네 폭에서横向 스크롤 없음 · 버튼/링크 텍스트 2줄 없음 · 헤더 1열 붕괴 — devtools 로 직접 측정 기록(또는 환경 불가 시 명시적 미검증).
- **대화형 미검증 솔직 명시**: 이 환경에서 브라우저 자동화가 없으면 preview 의 시각·클릭 검증은 "정적 서빙 + 코드 검토"로 대체하고 미검증 항목을 명시(거짓 성공 주장 금지).
- **M0 인계 이슈 #3 폐쇄**: ProfilePicker 이름변경/삭제가 인앱 Dialog 사용, 네이티브 prompt/confirm 0건(`rg 'globalThis\.(prompt|confirm)' src` 빈 결과).
- **기존 기능 회귀 없음**: `npm run check` · `npm test` · `npm run build` 전부 EXIT=0 — 출력 원문 RESULT 에 첨부. 기존 74 테스트 + 신규(있다면) 통과.
- **i18n 무결**: ko/en 양 로케일에서 깨진 문자열 없음 — `messages/{ko,en}.json` 키 집합 동일.
