## 1. 목표

배운 기법이 잊히지 않게 하는 연습 루프를 완성한다: 무엇을 언제 다시 풀지(FSRS), 얼마나 어렵게(적응 난이도), 어떤 형태로(혼합 세트), 그리고 그 결과를 학습자·보호자에게 보여주는 화면.

## 2. 산출물

1. **FSRS 스케줄러** `src/lib/srs/` — 순수 모듈. 카드 = 기법 × 난이도 밴드. `ts-fsrs` 채택 우선 검토(직접 구현 시 사유). **파라미터 전부 외부화**(아동 검증 근거가 없으므로 보수적 기본값 + 조정 가능, PLAN §4.3). 불규칙 사용(며칠 공백)에 견고해야 함 — 밀린 카드 폭탄 방지 상한.
2. **정확도 게이트** — 기법별 정확도 90% 도달 전에는 시간 요소 노출 금지. 게이트 통과 시 유창성 훈련(M5 공연 모드의 전제) 해금 표시.
3. **적응 난이도** — 최근 성공률이 80–90% 밴드를 벗어나면 생성기 파라미터(자릿수·올림 빈도)를 한 눈금 조정. 순수 함수 + 단위 테스트.
4. **오늘의 연습** `#/practice` — due 카드 기반 혼합 세트(interleaving: 서로 다른 기법 섞기 — "어떤 트릭을 쓸까" 판단 포함). 세션 5–10분 분량에서 자연스러운 종료 화면. 무한 이어하기 강요 금지.
5. **스트릭(관대)** — 일일 최소량 낮게, freeze 기본 제공, 상실 위협 연출 금지 (PLAN §4.2-11).
6. **학습자 진도 화면** `#/progress` — 기법별 숙련도(학습 전/학습 중/게이트 통과/유창), 최근 활동.
7. **보호자 리포트** `#/report` — 이번 주 배운 전략 + "아이와 나눌 대화 소재 1개"(예: "757+34를 왼쪽부터 계산하는 법을 물어보세요"). 텍스트 ko/en.
8. **시뮬레이션 테스트** — 가상 학습 기록(성실/불규칙/과잉 사용 시나리오)으로 스케줄·게이트·난이도 조정이 명세대로 동작하는지 검증.

## 3. 완료 기준

- 시뮬레이션 테스트 3개 시나리오 통과, 스케줄러·게이트·난이도 단위 테스트.
- preview 수동 확인: 레슨 완료 → 카드 생성 → 오늘의 연습에 등장 → 세션 종료 화면, 진도·리포트 화면 데이터 표시 — 결과 기록.
